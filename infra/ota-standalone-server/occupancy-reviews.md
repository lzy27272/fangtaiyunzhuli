# 门店出租率复盘与时点目标

入口：门店工作台 → 出租率复盘。点击“直达每日目标”可直接进入目标表。

## 业务口径

- 仅按入住日统计“在住＋已预订待入住房”的出租率，不统计下单日进单、收入或 ADR 目标。
- 采用 PMS 已合并的已售房量／PMS 统计房量，不能再把预订和入住字段相加。分母沿用 PMS 原口径，不自行猜测维修房、自用房是否扣除。
- 历史复盘按有效房量加权，不能简单平均日百分比。罗盘历史低于或等于 1% 的情况由已归档的房量重算，避免旧的比例／百分数歧义。
- 自然周为北京时间周一至周日；月报为自然月。周同比比较前 52 周的相同星期序列，月同比比较去年同月，均明确标注。
- 已结期且两期每日数据完整才给环比／同比；缺失不当作零。日末为 PMS 营业日切换前最后有效快照，不宣称已经过财务夜审。

## 建议与决策

默认时点为 12:00、15:00、18:00、21:00、23:00（北京时间）。目标周逐日匹配前一周同一星期几。

建议值以该日历史时点出租率为基线，不隐含自动增长幅度；展示相邻时点净增最多的时段并提示复核节假日、团单、房量。预订取消造成的下降会保留，不能当作新增订单量。

历史时点取截止时刻之前 90 分钟内最近的快照，不能使用之后的结果倒填。样本缺失时建议留空；可手工设定尚未到期的目标。

平台管理员或有本店权限的 OTA 运营经理：填入建议 → 调整百分比 → 填写决策说明 → 确认目标并生效。普通授权门店账号只读。所有目标在服务端按租户和门店隔离。

确认后生成版本、确认人、时间和说明。版本冲突拒绝覆盖；相同请求重试不产生第二版本。已过时点的目标锁定，不允许补设、删除或改写。目标保存失败不会返回成功，也不会修改 PMS／OTA 价格、库存或向企微群发。

## 自动归集与保留

沿用 `sifangguan-ota-analytics-import.timer`，每五分钟导入事实并刷新周／月汇总，因此每周一、每月初自动出现上个周期；断档后补入事实会继续更新。

- 小时事实 48 个月；每日经营事实 2 年；出租率周／月汇总 5 年。
- 时点与日明细导出最近 2 年，汇总导出最近 5 年。旧日事实到期不能将已归档的完整周期覆盖成残缺周期。
- 本地只读聚合缓存：`/var/lib/sifangguan-ota/analytics-retention/occupancy-history.json`，0600、原子替换。没有客人、订单身份、Cookie 或数据库凭据。
- 目标版本：`/var/lib/sifangguan-ota/occupancy-targets.json`，0600、原子替换，保留 5 年，已纳入发布保护。导入服务每五分钟将版本幂等归档至 `ota_analytics.occupancy_target_decision`，随既有 PostgreSQL 加密分层备份保存（归档前最多存在一个导入周期的备份延迟）。同一版本内容冲突会报警而不是覆盖。
- API 缓存未接通或 20 分钟未刷新会显式告警；当前快照 90 分钟未更新不判定实时达标。

## 发布注意事项

本功能需要同时发布 API、前端和 analytics 组件，不能只上传网页。

现有发布脚本已包含 `occupancy-review.mjs`，SQL/importer 改动会触发 analytics 配置。`configure-analytics-retention.sh` 创建汇总与目标归档表及相关函数、安装新版导入脚本、立即运行一次导入。既有事实不迁移、不删除；汇总表与缓存可由历史事实重建。

灾备时先恢复 PostgreSQL，再由管理员从 `occupancy_target_decision.decision` 聚合成 `{ "schemaVersion": 1, "plans": [...] }`，核对版本后原子恢复目标文件并设为 `sifangguan-ota` 所有、0600。不得用空目标文件覆盖已有版本。异机备份仍取决于服务器原有异机挂载配置，本功能不会代替或绕过该要求。

发布后核对：analytics timer/service 正常、`occupancy-history.json` 有 15 家（以实际授权目录为准）、登录后本店复盘可读、无权限账号不可写。不要为了验收在真实门店创建测试目标。

首次部署前的历史不会凭空补齐。2026-09-18 的核查显示现有归档始于 2026-09-12，当前周／月可能不完整，去年同期暂不可比较。
