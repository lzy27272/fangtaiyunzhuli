# Hotel AI OS V1.2 架构冻结记录

状态：已冻结  
日期：2026-07-17  
负责人：CTO / Lead Developer

## 产品定位

Hotel AI OS 是酒店集团第二管理体系，不是 OA、ERP、静态报表系统或简单 AI 聊天工具。

## 冻结管理链

```text
组织与权限中心
→ 企业标准中心
→ 三类业务入口（岗位工作数据、经营数据、AI主动发现）
→ AI分析中心
→ 企业规则中心
→ 任务执行中心
→ 绩效复盘中心
→ 企业知识中心
→ 反哺标准中心
```

## 不可破坏的架构约束

1. 模块边界独立；新 Agent 通过注册、工具和事件扩展，不修改核心底层。
2. 品牌、区域、门店、岗位、工作包、KPI、SOP、标准、规则、Agent 均以版本化配置管理。
3. `tenant_id` 是硬隔离边界；权限必须在服务端执行，前端隐藏不构成授权。
4. 员工、任职、岗位、角色分离，支持一人多岗、临时授权和有效期。
5. 标准中心定义“什么是正确”；知识中心沉淀经验，知识不能替代强制标准。
6. 规则引擎执行阈值、时间、状态、通知和升级；大模型不负责确定性规则判断。
7. 所有 AI 调用必须经过 AI Gateway，并记录模型、Prompt、Agent、工具、成本和审计信息。
8. 高影响 AI 建议必须经过人审；Agent 不直接连接业务数据库。

## Sprint 1 实现边界

本 Sprint 建立组织权限、标准中心基础、岗位工作数据、经营数据及 CEO/店总驾驶舱框架。AI 主动发现的事件契约保留，但不在 Sprint 1 执行模型调用；Rule Engine、任务闭环、绩效复盘和知识中心进入后续 Sprint。

## 首批验证角色

- 前台员工：一线工作数据。
- 客房主管：检查、图片和整改入口。
- 前厅主管：员工与班组管理。
- 店总：经营数据和管理视图。
