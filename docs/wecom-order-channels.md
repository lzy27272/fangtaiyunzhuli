# 播报渠道按实际订单显示

当日收益分析的“订单汇报”和“小时进单”不使用固定渠道占位。

- 当日汇总只展示该营业日下单且有有效或取消间夜的渠道；其他日期下单的记录不参与当日渠道选择。
- 小时／两小时／停播汇总只展示相应时段有新增或取消的渠道。
- 同一小节的所有数字使用该小节“渠道顺序”的同一排列；取消单独占有的渠道也保留。
- 当日或时段没有订单时明确显示无订单／无变动，不列出一串零渠道。
- 已识别的携程、美团、飞猪、抖音、前台、婚宴单独展示；仅未知来源归为“其他”，没有未知来源时不展示“其他”。
- PMS 显式渠道优先于价格类型、协议类型等辅助字段；不直接把任意原始文本写进消息。

例如，某店只有携程、抖音、前台和婚宴订单，就显示这四类；当天后来出现美团订单时，美团才进入渠道顺序。这里仍沿用原来的间夜统计口径，不把订单数当成间夜数。

## 兼容与发布

新采集输出 `PMS_ORDER_DETAIL_AGGREGATE_V2`，保留独立携程、前台和婚宴汇总。可信设备入库继续接收 V1 和旧版小时汇总，其他字段与隐私校验不放宽。

V1 曾把携程等来源合并进 OTHER。有保留订单明细时，播报预览重新聚合明细；没有明细时只显示可靠总数并提示更新采集端，不推断渠道拆分。旧明细已经记成 UNKNOWN 的来源不能仅靠旧记录恢复，需要新采集。

发布不重写历史播报、不修改订单或门店配置、不额外发送群消息；新渠道识别从下一次采集生效。测试覆盖分类、动态渠道、零值、取消、旧设备兼容、采集至播报的完整链路和企微消息字节限制。
