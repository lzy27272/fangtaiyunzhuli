# 贵州四方馆酒店管理有限公司中台 Pilot内部测试操作说明

版本：TECH-V0.2-PILOT.7  
访问地址：https://www.sfgzt.cn

## 一、登录方式

浏览器直接进入中台登录页，使用本人岗位对应的“中台应用账号”。站点不再使用浏览器Basic Auth弹窗，避免移动端和内置浏览器出现`ERR_INVALID_AUTH_CREDENTIALS`。

本机管理员凭据位置：`D:\SifangguanHotelAIOS\Pilot-Account-Access.txt`。

密码不会写入项目文档。向门店发放账号时，请一人一账号，通过私下安全渠道发送，不要在群聊中发送完整账号和密码。应用连续登录失败5次会临时锁定，避免反复试错。

## 二、第一次配置顺序

使用集团CEO账号登录后，按以下顺序操作：

1. 打开“组织与权限” → “门店与部门”，新增区域、门店和部门。
2. 切换到“岗位字典”，新增门店需要使用的岗位。
3. 切换到“人员与任职”，新增员工及登录账号。
4. 点击“分配任职”，选择员工、组织、岗位和业务角色；同一员工可重复分配多个任职，并指定一个主岗。
5. 打开“工作包中心”，新建工作包草稿，选择目标岗位、下发范围、已发布表单、周期和验收方式。
6. 打开该工作包的“查看版本与发布”，先“校验并发布”。
7. 再次打开同一工作包，选择负责人任职和目标门店，点击“下发并生成今日工作”。
8. 员工退出后用本人应用账号登录，在“我的工作”中填报并上传现场照片。

岗位、表单和工作包必须匹配。例如“前台客诉记录”应下发给前台岗位任职；系统会拒绝岗位、组织、任职或表单不匹配的提交。

主数据维护规则：

- “编辑”可修改组织、岗位或员工资料；为保护组织树，组织类型和上级组织不能在编辑时直接迁移。
- “停用”用于已投入使用的数据。停用组织、岗位或员工会结束相关有效任职/授权，重新启用后需要管理员重新分配。
- “删除”仅对已停用且从未被业务引用的数据开放。已有任职、权限、工作或任务历史的数据不会被物理删除，只保留为停用状态。

## 三、权限与数据隔离

- 集团CEO：租户全量组织与配置权限。
- 区域/运营角色：只查看授权区域及其下属门店。
- 店总/店助：只查看授权门店及下属部门、任务和风险。
- 主管：只查看授权部门或班组，可按权限复核、整改和验收。
- 岗位员工：只查看本人任职范围和本人工作，不能新建组织、岗位或工作包。
- 一人多岗：顶部“当前任职”决定当前工作上下文；工作数据绑定精确任职，不因切换岗位串岗。

任务下达范围：

- 集团CEO：可向集团内全部有效岗位任职下达任务，并查看集团授权范围内任务。
- 店总、店助、前厅主管、客房主管等门店管理岗：可向本人所在门店员工下达任务。
- OTA运营助理、OTA运营经理：可向全部门店的管理岗位下达任务，但跨店下达能力不会扩大其其他业务数据读取范围。
- 前台员工和基础客房员工：只接收、执行、提交结果，不能创建或下达任务。
- 任务不关联标准时由指定验收人执行并留痕人工验收；关联标准时必须先完成标准评价，再验收关闭。

如果员工看不到工作，依次检查：员工是否已有登录账号、是否分配了正确岗位、角色范围是否指向目标门店、工作包是否已发布、是否已下发给该员工任职。

## 四、当前可测试能力

- 新增、编辑、启用/停用区域、门店、部门、岗位和员工；未使用数据可受控删除。
- 员工账号资料维护、管理员密码重置和一人多岗任职。
- 真实账号登录、组织范围和角色权限隔离。
- 工作包创建、版本发布、岗位下发和当日工作生成。
- 前台员工、前厅主管、客房主管、店助、店总、OTA运营助理和OTA运营经理均已预置岗位专属日清工作包；当前有效任职已完成下发，后续新增任职需由管理员在工作包中心下发并生成工作。
- 岗位结构化填报、图片附件上传、工作提交。
- 工作台“今日待完成”“执行中任务”“待我验收”和门店驾驶舱摘要可直接进入相应筛选结果。
- CEO或管理岗创建并立即下达任务；接收人在“我的任务”和通知中心收到，提交结果后由指定验收人评价或人工验收关闭。
- 任务与通知页面每15秒静默刷新；新任务通常可在15秒内显示，空页也可点击“立即刷新”。
- 任务操作按钮仅向真实执行人或验收人显示；管理者的团队查看权不代表可代替员工提交。
- 团队工作、任务、标准评价、通知和规则中心现有闭环能力；清理历史UAT数据后，列表初始为空属于真实数据库结果，不会用演示数据填充。
- CEO、店助、店总和运营驾驶舱按权限读取真实经营、风险、工作和任务数据。

## 五、当前Pilot限制

- 暂不支持组织跨层级迁移、主数据批量导入；已有历史引用的数据禁止硬删除。
- 暂无员工自助找回密码；需要管理员重新分配账号或由技术人员处理。
- 这是内部测试版，不是TECH-V0.2正式生产发布，不接入自动调价、复杂OTA接口或多Agent自主协作。
- 历史名称含`UAT`、`UI-`或“Pilot网页验收”的自动验收组织、岗位、账号和关联业务数据已执行受控清理；后续验收脚本只能写入隔离UAT环境。

## 六、当前电脑作为服务器的要求

本系统现在运行在当前Windows电脑上。门店需要访问时必须满足：

- 电脑保持开机并连接互联网。
- 不进入睡眠或休眠。
- PostgreSQL、Core API、Caddy和Cloudflare Tunnel保持运行。
- Windows重启后需完成当前用户登录；`SifangguanPilotCoreApiUser`计划任务会检查并恢复Core API。

Caddy和Cloudflare Tunnel已经作为自动服务运行；如网页能打开但业务接口异常，先检查Core API和PostgreSQL状态，再检查Tunnel服务。

## 七、测试反馈格式

门店反馈问题时请同时提供：

- 发生时间。
- 登录角色和当前任职。
- 所在门店/部门。
- 操作页面和具体按钮。
- 页面截图，不包含密码。
- 预期结果与实际结果。
