## 一、推荐顺序

可以把受控人工登录作为下一阶段，但顺序必须是：

```text
确认专用最小权限账号与自动化许可
→ 准备隔离浏览器与UAT网络
→ 授权人员现场输入凭据并完成首次登录
→ 只读观察已知业务操作产生的请求
→ 输出无凭据、无住客信息的字段合同
→ 使用脱敏fixture离线开发适配器
→ 另行审批隔离UAT影子采集
```

不能采用“先把日常账号和Cookie交给开发，再边抓边猜接口”的方式。

## 二、登录前必须满足

- [x] 门店或集团确认该账号可用于受控测试；
- [ ] PMS厂商或合同条款允许只读自动化/接口观察；
- [x] 可以提供专用测试子账号或最小权限只读账号，不使用店总、财务或超级管理员日常账号；
- [ ] 明确账号责任人、门店业务复核人和测试时间窗；
- [x] 使用独立浏览器Profile或隔离UAT浏览器，不复用员工日常浏览器Profile；
- [x] 凭据只由授权人员在浏览器中现场输入，不发送给Codex或开发人员；
- [x] 本次密码、Cookie、Token和验证码仅存在于受控浏览器存储，未进入聊天、Git、日志、文档或fixture；
- [x] `message_enabled=false`，企业微信及正式运营群继续禁发；
- [ ] 明确退出、吊销、会话失效和重新认证流程。

任一项未满足时不得登录。

受控浏览器辅助进程必须与现有OTA Connector Worker分离。当前Worker离线边界禁止直接引入Playwright或驱动浏览器；不得为登录方便放宽该门禁。

## 三、第一次登录只允许做什么

1. 授权人员打开已知登录入口并现场完成登录、验证码或MFA。
   - 登录入口固定为`https://pms.meituan.com/`；
   - `https://pms.meituan.com/hotelpms/api/v1/report/lion/manager/workbench/room`是登录后业务接口，不作为登录入口直接调用。
2. 只进入喷水池态六酒店已授权范围，不切换其他酒店或租户。
3. 只执行正常页面查看，不创建、修改、取消订单，不调整价格、库存、房态或门店配置。
4. 只观察已知页面操作产生的请求，不进行路径枚举、参数爆破、接口扫描或批量回放。
5. 首轮仅确认：
   - 登录后会话机制的类型，不记录具体值；
   - 已知`room`地址的HTTP方法、Content-Type和非秘密参数名称；
   - 响应是否包含实体房型、有效总房量、实际可售量、营业日或观察时间字段；
   - 是否存在明确的分页、更新时间或错误码。
6. 发现跨店数据、住客个人信息、财务明细、写操作、验证码绕过、风控提示或访问限制时立即停止。

## 四、允许留存的证据

只允许留存经复核的脱敏材料：

- 接口路径、HTTP方法、非秘密参数名称和字段名称；
- 不具识别性的代表值；
- 字段含义、时间语义、分页、限流和错误码说明；
- 脱敏文件的SHA-256；
- 观察时间、操作者账号别名和复核人。

不得提交原始HAR。若必须从开发者工具整理证据，由授权人员先删除：

- `Cookie`、`Authorization`、Token、session、签名、验证码和全部请求头秘密；
- 住客姓名、手机号、证件号、地址、订单备注及其他个人信息；
- 可复用门店ID组合、跨店数据和非试点门店内容；
- 任何可执行写请求或完整登录响应。

## 五、必须补齐的数据能力

单一`room`页面或地址不足以支撑完整闭环。登录观察需要分别找到受许可的只读数据来源：

| 数据流 | 必须证明的内容 |
|---|---|
| PMS营业日 | 营业日字段、夜审后实际切换及来源更新时间 |
| 订单间夜 | 稳定键、创建/修改/取消时间、改期、缩住、减房和多间多晚 |
| 房费收入 | 仅房费、钟点房房费、非房费排除、退款与冲销，精确到分 |
| 实体库存 | 实体房型稳定ID/名称、有效总房量、实际可售量和观察时间 |
| 采集完整性 | 分页、增量水位、历史范围、限流、错误码和Schema变化 |

## 六、登录后仍不能做什么

即使首次人工登录成功，也不能自动解锁：

- Cookie/Token提取和程序化复用；
- 真实连接器编码、候选登记或批准；
- Worker真实profile、外部egress和`test/activate/run`；
- 自动抓取、P1运行、小时简报或企业微信投递；
- 双店连续3个PMS营业日UAT和生产发布。

登录观察结果必须先形成脱敏字段能力矩阵和人工金标准，完成安全评审后才能申请离线适配器开发。
