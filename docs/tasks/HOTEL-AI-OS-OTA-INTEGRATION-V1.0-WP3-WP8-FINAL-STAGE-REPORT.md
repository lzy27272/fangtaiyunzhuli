## 1. 本次落地范围

本次从已完成的 WP0-WP2 连续实施到 WP8，不导入真实账号、密码、Cookie、Token、Webhook 或住客资料，不访问真实 PMS/OTA，不发送真实企业微信消息，也不把页面可见或模拟结果解释为厂商授权或生产验收。

核心迁移为 `V8__wp3_to_wp8_final_stage_control_plane.sql`，使用现有 V2 采集、标准化、库存、订单、快照、简报、Outbox 基础，不复制另一套经营事实。

## 2. WP3：只读同步、数据质量与留存

- 复用版本化连接器、采集批次、采集尝试、水位和来源状态。
- 新增追加式数据质量事件，可表达完整、部分、不可用、过期、恢复核验、去重和金标准比对。
- 标准经营事实、衍生指标、简报、AI 建议、预警、任务、调价和普通审计统一保留 **365 天**。
- 脱敏原始证据保留 **30 天**；不允许冷归档；法律保全由后续受控删除任务跳过。
- 来源缺失状态保持 `UNAVAILABLE`，不得合成为数值零。

## 3. WP4：异常优先首页

- 新增 `ota.anomaly_first_dashboard` 安全调用者视图，遵守底层 FORCE RLS。
- P1、P2、P3 严格排序；展示门店、渠道、指标、证据截止时间和数据质量。
- 外部后台只保存已批准的 HTTPS 主机与固定路径前缀；查询字符串被数据库约束禁止。
- 预警关闭必须追加新的关闭事件并携带证据哈希，不能覆盖历史。

## 4. WP5：预警、任务、站内和企业微信

- P1、P2 首次通知和 SLA 升级均强制路由为 `IN_APP_AND_WECOM`。
- P3 不创建即时任务，只进入 `DAILY_WECOM_SUMMARY`。
- 以预警、阶段和幂等键去重。
- 当前数据库与默认适配器均为 `UAT_ONLY`、`external_delivery_allowed=false`，因此不会误发正式群。
- 旧云端运行包的 P2 路由模块已加入发布清单，并加入 Node 回归测试。

## 5. WP6：模型治理

- 门店级版本化 AI 策略覆盖计划简报、P1/P2 解释、P3 每日摘要和人工调用。
- 模型仅接收脱敏结构化事实；离线评测记录事实落地、无 PII、结构合法和回退状态。
- 确定性回退为硬门禁；模型不可用时不影响事实、严重度、任务和简报。
- 默认 `ModelGateway` 关闭，未通过受控后台配置模型供应方和密钥前不会发出调用。

## 6. WP7：受控标准零售价

- 不可变预览仅允许 `STANDARD_RETAIL`，冻结房型/日期、当前价、建议区间、映射与策略哈希。
- 门店岗位和 OTA 运营助理可在授权门店内发起；超出建议区间无法提交。
- 仅 OTA 运营经理可“审核通过并同步”，且审批账号必须与发起账号不同。
- 执行前重验有效期、正式写入授权、写入 UAT、映射/策略版本和连接器健康。
- 超时语义为 `UNKNOWN_MANUAL_REVIEW`，禁止盲重试；成功必须渠道回读一致。
- 默认价格写入适配器和数据库 `external_execution_allowed` 均硬关闭。真正开放需独立向前迁移、正式授权和写入 UAT 证据，不能靠改配置绕过。

## 7. WP8：全门店 7 日 UAT 与逐店发布

- 验收按租户×门店独立记录 7 个 PMS 营业日证据。
- 每日记录连接器覆盖、计划采集成功率、关键窗口、金标准、重复投递和 PII 检查。
- 只有 7 个不同营业日、采集成功率不低于 99%、关键窗口和金标准全通过、重复投递与 PII 均为 0，并由授权账号签署时，门店才可标记待发布。
- 未通过门店明确保持原服务，不阻塞其他已通过门店。

## 8. 已实施的失效保护

1. `DisabledModelGateway`：无受控配置时拒绝调用模型。
2. `DisabledStandardRetailPriceWriter`：无正式授权和写入 UAT 时拒绝渠道写入。
3. 企业微信仅生成 UAT 投递意图，不执行真实外部发送。
4. 新增表全部 FORCE RLS；策略、证据、预览和事件均追加式。
5. 数据库没有真实秘密或住客 PII 字段。
