## 二、本轮已实现

### 2.1 Raw / Standard 同事务持久化

- 采集运行、原始证据记录和标准化记录采用同一事务边界。
- Raw 记录保留受控证据引用、SHA-256、解析版本和必要哈希；Standard 记录保存隐私最小化后的标准字段，并与对应 Raw 记录建立关联。
- 任一标准记录校验或写入失败时，整批事实写入失败，不允许出现只写 Raw、只写 Standard 或标准记录悬空的半成功状态。
- 幂等键和稳定标识继续用于抵御作业重试导致的重复事实。

### 2.2 水位推进门禁

- 只有 `SUCCESS + COMPLETE` 的采集结果，在全部应写记录成功后，才允许提交候选水位。
- `PARTIAL`、`AUTH_REQUIRED`、`FAILED` 或不可用结果均不得推进水位。
- 失败、部分成功和来源不可用不得伪造为 0，也不得用旧数据冒充当前完整数据。
- 水位类型、游标内容、来源更新时间和观测时间均进入安全校验。

### 2.3 CollectionResult 严格校验

已在 Worker 连接器执行出口接入 `CollectionResultValidator`，在结果进入持久化前统一校验：

- `status` 与 `completeness` 的合法组合；
- 候选水位及时间先后关系；
- 每条 Envelope 的 tenant、hotel、connector、run 和 stream 必须与领取到的请求完全一致；
- Envelope 的来源系统必须与连接器声明一致；
- 证据引用只允许受控协议，且必须具备合法 SHA-256；
- 记录 ID、幂等键、`recordType`、来源记录键和来源更新时间必须安全、稳定且无批内冲突。

非法结果采用固定、可审计的安全原因码失败，不透传可能包含账号、凭据、Cookie、Token、个人信息或厂商响应正文的异常消息。

### 2.4 Capability / Schema 指纹与漂移框架

- 已提供确定性的 capability 指纹，覆盖来源系统、交互授权属性、能力集合和数据流集合。
- 已提供确定性的标准记录 schema 指纹，覆盖记录类型、实现类型和记录字段结构。
- 已提供基线对象、代码审查后的标准记录 schema 白名单和运行时漂移检测器；连接器身份、适配器版本、能力或 schema 与启动时冻结基线不一致时一律 Fail Closed。
- 漂移检测已接入普通采集执行链，不以首个采集结果动态建立 schema 基线。
- 本轮交付的是离线通用框架，不包含任何 PMS、携程或美团厂商适配器及其持久化生产批准基线；真实连接器解锁前仍需建立按版本审批、轮换和回滚流程。

### 2.5 Real Profile 默认关闭并主动拒绝

- 真实连接器总开关 `ota.sprint2.real.enabled` 默认值为 `false`。
- 仅设置属性而不启用 `sprint2-real` profile，不会开启真实连接器。
- `sprint2-real` 与 `sprint1-simulation` 不允许同时启用。
- Sprint 2A 尚未提供外部 SecretStore 和网络 egress 实现，因此即使 profile 与属性同时打开，Worker 仍主动拒绝真实连接器启动。
- 当前不存在绕过门禁的真实 PMS、OTA、浏览器自动化或企业微信网络实现。

### 2.6 V3 会话绑定与分钟槽

- V3 已纳入数据库会话身份绑定约束，目标是使运行身份与受控 service principal 建立强绑定，降低连接池会话身份残留或调用方自报身份造成的越权风险。
- V3 已纳入分钟调度槽语义，用稳定分钟槽约束同一计划时点的派发与幂等，避免秒级触发差异产生重复小时作业。
- 相关迁移、静态门禁和代码已进入本轮实现范围。
- PostgreSQL 14.22 已完成 Flyway V1→V2→V3、会话身份绑定、错误 principal 拒绝、精确 ACL、分钟槽幂等以及 `NORMAL 10:05` 调度、领取、连接器执行、事实与 checkpoint 闭环。

### 2.7 历史 Secret 展示修复

- 已收紧连接器配置读取与展示逻辑：切换到不需要 Secret 的适配器后，不再展示历史 Secret binding。
- 后台返回与前端展示不得回显 Secret 值、旧绑定细节或可据此还原凭据的内容。
- 该修复只处理历史 Secret 的可见性和错误沿用风险，不代表真实 SecretStore、轮换、吊销和生产注入链已经完成。
