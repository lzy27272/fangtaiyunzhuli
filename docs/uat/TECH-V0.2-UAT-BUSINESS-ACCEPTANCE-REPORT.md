Sprint 3状态：冻结，未启动

## 1. 执行结论

Sprint 2技术验收候选已经通过，技术验收结论不撤销。本轮开始业务UAT后，准入检查及业务链路核对发现多个P1阻断项，六角色和三个指定场景尚不能在真实业务环境中完整执行，因此TECH-V0.2暂不具备正式发布条件。

本报告不使用演示回退数据代替真实UAT，不把后端自动化测试等同于业务验收，也不生成无法追溯到真实API和真实数据库的“通过截图”。

最终判定：

```text
技术候选：通过
业务UAT：阻断
TECH-V0.2正式发布：NO-GO
Sprint 3：不得启动
当前正式版本：TECH-V0.1
```

## 5. 三个重点业务场景

### 5.1 场景A：客房卫生问题

目标链路：

```text
上传照片
→ 关联卫生标准
→ 形成评价
→ 生成整改任务
→ 主管执行
→ 店长验收
```

| 步骤 | 当前能力 | 结果 |
|---|---|---|
| 上传照片 | 只有附件元数据表和元数据接口；无真实对象上传、扫描、前端选择控件 | FAIL |
| 关联卫生标准 | 标准版本、工作包标准关联和评价模型具备 | BLOCKED，缺少UAT数据 |
| 形成评价 | 确定性评价API具备；前端只有查询详情 | FAIL，业务页面无法创建 |
| 生成整改任务 | 工作记录被复核拒绝后可由规则建任务 | BLOCKED，需额外拒绝动作且无真实规则数据 |
| 主管执行 | 任务状态动作具备 | BLOCKED，前序未形成任务 |
| 店长验收 | 任务通过/返工动作具备 | BLOCKED，前序未形成任务 |

场景结论：FAIL。结构化API可以构造部分闭环，但不满足“图片检查”的业务验收要求。

### 5.2 场景B：客诉问题

目标链路：

```text
员工提交客诉
→ 标准判断
→ 规则触发
→ 任务生成
→ 跟踪关闭
```

现有工作记录提交事件没有携带足够的客诉业务事实，例如表单代码、记录类型、客诉等级和业务载荷。规则无法安全判断“这是客诉”或“仅重大客诉触发”，直接配置可能误命中同岗位其他记录。

人工创建任务可以完成任务状态流转，但不满足本场景“规则触发”的验收要求。

场景结论：FAIL。需要专用`ComplaintReported`事件或完整事件事实投影后重测。

### 5.3 场景C：工作未完成

目标链路：

```text
员工未提交
→ 规则检测
→ 提醒
→ 升级
```

`work_expectation`数据模型允许`MISSED`状态，但当前没有到期扫描Worker、受控处理接口、状态迁移服务和`WorkExpectationMissed`事件。任务中心的逾期处理只能处理已经存在的任务，不能发现“岗位工作未提交”。

场景结论：FAIL。该链路不能通过直接修改数据库状态代替业务UAT。

7. 增加可安全识别客诉的事件事实或专用事件。
8. 增加未提交到期处理、`WorkExpectationMissed`事件、提醒和升级执行。
