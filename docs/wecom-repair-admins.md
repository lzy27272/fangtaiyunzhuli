# 播报修复管理员：人员名单、多店授权与离职解绑

入口：顶部导航 **人员与权限 → 企微管理与审批**。这是全平台权限配置，不属于任何单一门店；无需先打开门店。仅平台管理员可读取完整名单和修改授权。

- 审批人、已绑定人员、多店授权、备用配对码及离职自动解绑统一在此管理。新增人员不会默认选择任何门店，必须明确勾选负责范围。
- 同页底部“机器人连接与全局修复权限”集中管理共用机器人凭据、启停和全局接收人的跨店处理权限。机器人只需配置一次。
- 门店 → 播报记录仅展示本店绑定人数（平台管理员可看本店人员姓名），通过“前往人员与权限配置”直接跳到全局企微页，不在门店里编辑全局权限。
- 每家门店自己的群机器人、播报时段、频率及群修复链接开关仍保留在门店播报设置中。
- 此次入口迁移不修改存储格式、审批人选择、绑定关系或权限；继续使用原有接口与版本校验。此前未保存的勾选不属于已保存配置，刷新后需重新核对并保存。

## 已绑定人员

### 新人员：自动识别账号，无需手填

1. 员工在机器人单聊发送“激活 真实姓名”；只发“激活”也会登记，姓名可由管理员补充。系统仅从已配置机器人的消息发送者取得账号，不按姓名猜测，也不补录历史消息。
2. 管理员进入“人员与权限 → 企微管理与审批 → 待授权人员”，选择人员并勾选一家或多家门店，核对员工身份后点击“批准并绑定”。账号只读，无需填写机器人账号或通讯录账号。
3. 批准后立即获得所选门店权限，不需要再次配对或激活。员工可发送“状态”确认。仅登记不获得任何权限，登记24小时过期后需本人重发；重复消息不重复建人。撤权或离职已解绑人员不能自行重新登记。
4. 该路径不会自动关联通讯录账号，也不会授予全局权限或审批权。离职自动解绑仍须核对通讯录关联；页面持续提示尚未关联。另有“申请 003 真实姓名”路径可让指定审批人在企微私聊卡片直接批准。
5. 原手填账号表单移入“审批与高级设置 → 备用方式：手工预授权（需账号）”，不再作为免输账号主入口。账号采集及申请状态仍在原加密事务内存储，使用原平台管理员接口、版本冲突校验及审计。

- 显示机器人回调中的企微账号、姓名备注、岗位标记、负责门店、是否属于全局接收人。
- 老绑定不丢失；接通下方只读通讯录后，人员卡片优先显示企业微信通讯录名称，人工备注单独保留。没有精确匹配时显示备注或“企微名称待匹配”，同时直接展示账号，避免把不同人员混淆。
- “编辑姓名 / 门店”可一次调整此人的负责门店，不影响其他人员或该人员原有全局接收身份。“解绑此人”须二次确认，撤销此人全部全局与门店权限，保留解绑记录。
- 全局接收人的跨门店执行权仍由原有显式授权开关控制；给运营经理勾选几家店不会将其升级为全局管理员。

## 通讯录名称同步（只读）

入口：同页“人员名单 → 通讯录名称同步”。平台管理员填写本企业**自建应用 Secret**，企业 ID 沿用已有通讯录回调配置。不是机器人通信密钥、回调 Token 或 EncodingAESKey。应用可见范围需要覆盖员工所在部门，并在企业可信 IP 中允许本系统服务器；优先复用符合范围的现有自建应用，不覆盖其他应用设置。

- 点击“保存并同步名称”后立即读取一次，此后每 6 小时自动刷新，也可点击“同步企微名称”。失败后自动重试间隔为 1 小时，显示可操作的原因，保留上次成功结果；未配置不会发出网络请求。停用后停止同步及名称匹配，不改变授权。
- 按官方[部门 ID 列表](https://developer.work.weixin.qq.com/document/path/95350)枚举可见部门，逐个调用[部门成员简单列表](https://developer.work.weixin.qq.com/document/path/90200)。不使用已经取消的 `fetch_child` 参数。仅 GET 官方固定域名，不跟随重定向，不调用通讯录写入接口。
- 只持久化 `{userId, name}`。部门 ID 仅临时用于请求，不保存部门资料、手机号、邮箱、头像、响应原文或访问令牌。Secret 与姓名缓存均进入现有加密凭据事务，普通状态接口不返回 Secret；完整名单只对平台管理员开放。
- 名称优先按人工核对过的通讯录账号匹配；无该关联时，仅允许本企业机器人账号与通讯录账号完全相等的展示匹配。找不到已关联账号时不能退回另一个同名/相似账号；不会按姓名、手机号或 `open_userid` 猜测。密文样式账号不能自动转换，需人工核对关联。
- 通讯录名称不同于个人微信昵称。员工填写姓名、管理员备注、通讯录名称分开标识。名称匹配**不建立离职关联、不授予门店/全局/审批权限**，缺失人员或读取失败不会触发解绑。并发撤权优先保留，后台同步只合并自己的读取状态，不覆盖其他配置。
- 单次请求最长 10 秒，总同步最长 55 秒，最多 500 个部门、10000 个姓名账号，响应上限 2 MiB。任何部门失败或重复账号名称冲突时整批不覆盖缓存。企业或读取配置变化时丢弃在途结果。

## 企业微信简易绑定审批（新人员推荐）

首次由平台管理员展开同一页面的“审批与高级设置 → 企业微信简易绑定审批” → “配置审批人”，启用功能，勾选自己与另一位运营负责人，点击“保存审批设置”。最多两位、任一人审批即可，不需要会签。升级默认关闭且不自动勾选；播报接收人不会自动成为审批人。

- 候选人必须已经绑定且核对了通讯录身份，通讯录回调已验证。没有出现在可选名单时，先为负责人完成现有绑定并编辑关联。授予审批权相当于允许为其他人员授予申请所列任意门店的修复权限，不只是通知订阅；只勾选信任的负责人。
- 员工打开统一机器人单聊，发送 `申请 003 张三`；运营经理可发送 `申请 003,005 张三`，一次最多20家。姓名为员工填写，真实机器人账号由接收事件提供。仅发 `003` 或“激活”不会直接获得权限。
- 两位指定审批人分别收到私聊按钮卡片，核对申请账号、员工填写姓名及完整门店范围，再点“同意绑定”或“拒绝”。第一位有效决定落盘后即生效，另一人再点击仅显示已处理；申请人和另一审批人收到结果通知。不会授予申请人全局接收权或审批权，也不自动触发PMS恢复/播报。
- 待审批没有门店权限。员工可发“申请状态”或“取消申请”；24小时过期，每账号24小时最多5次申请，同一待审批申请不会重复推送。申请记录在加密凭据中保存，保留最近30天、上限500条；后台显示最近50条。
- 转发卡片、群聊、其他机器人、他人代点、非指定审批人和自己审批自己均不能授权。撤权或已关联的通讯录离职通知会即时阻止审批；申请人资料或门店权限变更后旧申请失效。改变审批配置取消全部待审批申请，需要员工重提。
- 发送前保存发送占位。无回执、超时或发送中重启标记“结果待确认”，不自动重复推送；需核对企微，确需重提由员工先取消申请。服务器离线时未发送任务等待恢复。决策和门店授权同一持久化事务完成，保存失败不报告成功。结果通知失败不回滚已经保存的决定，员工仍可查询。
- 新员工经卡片批准后，姓名明确标记“员工填写”。不会猜测机器人账号对应的通讯录 UserID；**未关联者的离职自动解绑尚未生效**，需要管理员按下方步骤核对关联。已解绑/离职的已知账号不能靠重新申请恢复权限。
- 每条申请保留实际账号、申请范围、提交/处理时间和决定人，审批配置修改沿用平台管理员的版本控制与操作审计。仅后台管理员可读取完整申请清单。

卡片能力采用[企业微信官方智能机器人 SDK](https://github.com/WecomTeam/aibot-node-sdk)现有的主动模板卡片和按钮回调；这是本系统的简易绑定审批，不会创建企业微信工作台的原生审批单。

## 免配对码预授权（备用方式）

机器人由平台统一配置一次，不需要逐店重新配置编号/密钥；员工仍需能进入企业内该机器人会话。

- 已绑定人员：在“人员名单”按姓名备注或账号搜索，点击“编辑姓名 / 门店”；勾选多店后保存立即生效，不必再次联系员工，也不改变原有全局身份。
- 新人员：管理员核对并填写机器人实际 UserID 与同一人的通讯录 UserID，填写姓名、选择门店并确认身份。两个账号不保证相同，不能用姓名或手机号推测；身份不确定时使用备用配对码。此入口目前不是全企业通讯录选择器，完整姓名/部门同步需要另行配置通讯录读取权限。
- 新人员预授权要求本企业通讯录回调已经验证。后台先显示“待首次激活”，不会接收或操作门店任务；收到指定机器人、指定账号的有效单聊进入事件后，原子写入全部门店授权并回复成功。官方进入事件通常每天首次进入才触发，当天已打开过可发送“激活”；普通单聊消息也可完成激活，但首次激活消息不执行额外修复操作。
- 事件中包含企业标识时必须匹配配置企业；不同机器人、群聊、旧进入事件、其他账号都不能激活。激活前重新校验门店存在性及容量，保存失败不授予权限、不回复成功，可重试。
- 名单显示待激活门店和激活成功时间，5 秒刷新。预授权支持编辑和撤销；手动解绑或有效通讯录离职通知同时取消待激活授权，旧入口不能复活权限。
- 预授权和激活仅管理身份/权限，不自动触发采集、修复、播报或全员通知。测试使用离线机器人和本地合成账号，不向真实员工发送测试消息。

## 24 小时绑定码：一次绑定多家门店

1. 在页面顶部“新增绑定”点击“生成绑定码（24小时）”，填写姓名备注、岗位并勾选负责门店。无需输入企微账号；门店不会默认全选。
2. 生成后自动定位到人员名单上方的醒目结果卡，展示绑定指令、接收人、门店数量及准确到期时间。点击“复制绑定指令”，仅私发给指定人员，让本人在机器人单聊发送一次“绑定 六位码”。授权门店和使用须知可展开查看。
3. 成功后全部所选门店同时授权；任一门店不存在或超出容量（每店 20 人）则整体失败。新绑定码从生成时起 **24 小时**有效，最多尝试 5 次，成功后失效；新码替换旧码。旧码不自动延期。
4. 已绑定账号扩展门店可直接编辑，不需重复配对。不要把配对码发到多人群或转交其他人。
5. 明文仅在生成时返回，页面刷新后不能重新读取；仍有效时显示到期提示，可显式重新生成。服务重启或权限变更可能提前作废，部署后请生成新码。后台仍只保存码的哈希，不将明文写入浏览器存储或日志。
6. 页面按“新增绑定、人员名单、审批与高级设置”分区。人员卡片优先展示企微名称、账号、备注、岗位、门店和操作，离职关联详情按需展开；审批、手工预授权和离职配置默认收起，不再把绑定码埋在人员列表末尾。

## 企业微信离职自动解绑

智能机器人长连接的会话事件不等于通讯录变更事件。此功能使用独立的通讯录回调，机器人通信密钥不能替代回调 Token / EncodingAESKey。

1. 企业微信管理员确认本企业可以配置通讯录同步“接收事件服务器”，并覆盖需管理的员工。如果已有系统占用该回调，不要直接覆盖，应协调该系统按企业微信原始签名加密请求转发，或选择官方支持的独立接入方式。
2. 在本系统“离职自动解绑”输入企业 ID、回调 Token、43 位 EncodingAESKey 并保存。全部配置保存在现有加密凭据事务中，接口不会返回密钥。
3. 在企业微信后台填写页面生成的 HTTPS 回调地址以及相同 Token / EncodingAESKey，并保存验证。当前生产入口地址应为 `https://www.sfgzt.cn/api/v1/ota-console/wecom-repair-directory/callback`；由既有 OTA 公网代理转发到 Node API，不另开公网端口。
4. 对每位绑定人员点击“编辑姓名 / 门店”，填写同一企业通讯录中的成员账号 UserID，人工确认其确实与机器人账号属于同一个人。不能用姓名、手机号、open_userid 替代，也不能假定机器人 ID 一定等于通讯录 ID。
5. 页面显示回调验证时间、已关联人数、尚未关联人数和最近事件。回调验证通过只证明接收配置连通；必须关联到具体人员，才能处理该人员的离职。

收到有效的 `change_contact/delete_user` 或 `change_contact/update_user` 且 `Status=2` 后，撤销精确关联人员的全部绑定，旧修复卡片的执行授权和排队中的私聊消息均重新检查。通讯录 UserID 的正常更名通知会更新关联，不自动恢复已离职人员。正在执行的外部操作不能倒退，已发消息不能撤回。

签名、企业标识或时间校验失败不做人员变更；网络错误、登录失败、退出群聊不会被当作离职。写盘失败不报告成功，企业微信可重试。接入前已发生的离职不会自动补发，需人工核查旧名单并解绑。

自动解绑依赖企业微信送达事件及服务可用性，不是全量在职扫描。首次上线需由企业微信管理员完成外部配置，并用专门测试成员做一次真实删除/禁用验收，不能把本地加密回调测试当成线上已经接通。
