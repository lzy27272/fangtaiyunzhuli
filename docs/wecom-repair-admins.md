# 播报修复管理员：人员名单、多店授权与离职解绑

入口：门店 → 播报设置 → 企业微信修复助手 → 已绑定人员与多店授权。仅平台管理员可读取完整名单和修改授权。

## 已绑定人员

- 显示机器人回调中的企微账号、姓名备注、岗位标记、负责门店、是否属于全局接收人。
- 老绑定不丢失；此前未保存姓名的人员显示“待补充姓名”，由管理员核对后补录。姓名是人工备注，不冒充已从通讯录核验的真实姓名。
- “编辑姓名 / 门店”可一次调整此人的负责门店，不影响其他人员或该人员原有全局接收身份。“解绑此人”须二次确认，撤销此人全部全局与门店权限，保留解绑记录。
- 全局接收人的跨门店执行权仍由原有显式授权开关控制；给运营经理勾选几家店不会将其升级为全局管理员。

## 一次绑定多家门店

1. 点击“新增 / 多店绑定”，填写姓名备注，选择运营经理及其负责门店。
2. 生成一个配对码，交给指定人员，让对方在与机器人的单聊中发送一次“绑定 六位码”。
3. 成功后全部所选门店同时授权；任一门店不存在或超出容量（每店 20 人）则整体失败。配对码 10 分钟有效，最多尝试 5 次，成功后失效；新码替换旧码。
4. 已绑定账号扩展门店可直接编辑，不需重复配对。不要把配对码发到多人群或转交其他人。

## 企业微信离职自动解绑

智能机器人长连接的会话事件不等于通讯录变更事件。此功能使用独立的通讯录回调，机器人通信密钥不能替代回调 Token / EncodingAESKey。

1. 企业微信管理员确认本企业可以配置通讯录同步“接收事件服务器”，并覆盖需管理的员工。如果已有系统占用该回调，不要直接覆盖，应协调该系统按企业微信原始签名加密请求转发，或选择官方支持的独立接入方式。
2. 在本系统“离职自动解绑”输入企业 ID、回调 Token、43 位 EncodingAESKey 并保存。全部配置保存在现有加密凭据事务中，接口不会返回密钥。
3. 在企业微信后台填写页面生成的 HTTPS 回调地址以及相同 Token / EncodingAESKey，并保存验证。当前生产入口地址应为 `https://www.sfgzt.cn/api/v1/ota-console/wecom-repair-directory/callback`；由既有 OTA 公网代理转发到 Node API，不另开公网端口。
4. 对每位绑定人员点击“编辑姓名 / 门店”，填写同一企业通讯录中的成员账号 UserID，人工确认其确实与机器人账号属于同一个人。不能用姓名、手机号、open_userid 替代，也不能假定机器人 ID 一定等于通讯录 ID。
5. 页面显示回调验证时间、已关联人数、尚未关联人数和最近事件。回调验证通过只证明接收配置连通；必须关联到具体人员，才能处理该人员的离职。

收到有效的 `change_contact/delete_user` 或 `change_contact/update_user` 且 `Status=2` 后，撤销精确关联人员的全部绑定，旧修复卡片的执行授权和排队中的私聊消息均重新检查。通讯录 UserID 的正常更名通知会更新关联，不自动恢复已离职人员。正在执行的外部操作不能倒退，已发消息不能撤回。

签名、企业标识或时间校验失败不做人员变更；网络错误、登录失败、退出群聊不会被当作离职。写盘失败不报告成功，企业微信可重试。接入前已发生的离职不会自动补发，需人工核查旧名单并解绑。

自动解绑依赖企业微信送达事件及服务可用性，不是全量在职扫描。首次上线需由企业微信管理员完成外部配置，并用专门测试成员做一次真实删除/禁用验收，不能把本地加密回调测试当成线上已经接通。
