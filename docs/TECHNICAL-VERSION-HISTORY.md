## 0. 文档职责

本文件记录系统实际实现和验收到哪个技术版本，以及下一版本需要达到什么完成门槛。

规则：

- 只有规划和方案时，状态只能是“规划中”。
- 已经开始编码才可以标记“开发中”。
- 测试通过但业务未验收，只能标记“待验收”。
- 只有测试、验收、制品和文档齐全，才能标记“已发布”。
- 产品蓝图版本和技术发行版本必须分开记录。

## 1. 四条版本序列

| 版本类型 | 用途 | 升级条件 |
|---|---|---|
| PRODUCT-Vx.x | 产品定位、管理链、中心边界和设计原因 | 产品架构发生变化 |
| TECH-Vx.x | 实际完成并验收的系统能力 | 可独立验收的技术里程碑完成 |
| API-Vx | HTTP向后兼容边界 | 发生破坏性接口变化 |
| DB-Vx | Flyway数据库迁移位置 | 新增正式迁移 |

补充制品版本：

- OpenAPI文档版本记录接口契约制品。
- 后端JAR版本记录构建制品。
- 前端构建版本应在正式发布时增加构建号或Git提交号。

## 2. 技术版本状态

| 状态 | 含义 |
|---|---|
| 规划中 | 只有目标、范围和方案，尚未编码 |
| 开发中 | 已进入代码、迁移或页面实施 |
| 测试中 | 功能范围冻结，正在执行测试 |
| 待验收 | 测试已通过，等待产品或业务验收 |
| 已发布 | 验收通过，制品、迁移和文档可追溯 |
| 已废弃 | 停止新增能力，但可能仍在运行 |
| 已退役 | 不再部署和维护 |

### 10.2 正式使用后

- 主版本：发生需要明确迁移的破坏性变化。
- 次版本：向后兼容的新能力。
- 修订版本：向后兼容的修复、安全或性能改进。

### 10.3 不提升TECH版本的情况

- 仅讨论方案。
- 尚未编码的需求。
- 不改变系统行为的文字修正。
- 未通过验收的中间构建。

## 12. 固定维护规则

### 12.1 开始变更时

1. 在CHANGELOG.md的Unreleased创建CHG记录。
2. 指定目标TECH版本。
3. 确认是否影响PRODUCT蓝图。
4. 记录数据库、API、权限、历史数据和回滚影响。

### 12.2 开发过程中

1. 数据库只新增Flyway迁移，不改已发布迁移。
2. OpenAPI与Controller同步更新。
3. 权限矩阵和租户隔离测试同步更新。
4. 测试报告记录新增和回归结果。

### 12.3 验收发布时

1. 把技术版本状态改为已发布。
2. 把对应Change Log从Unreleased移入正式版本。
3. 记录迁移范围、API版本、制品校验和和Git标签。
4. 链接测试报告、验收报告和截图。
5. 记录已知问题和恢复方案。

### 12.4 需要更新产品蓝图时

以下情况必须先更新docs/HOTEL-AI-OS-PRODUCT-BLUEPRINT.md：

- 产品定位变化。
- 顶层管理链变化。
- 新增或删除核心中心。
- 组织、一人多岗、权限隔离或标准版本原则变化。
- AI与确定性规则的职责边界变化。
