# KPI考核与绩效复盘中心技术冻结

状态：已批准开发
日期：2026-08-12
归属：四方馆AI中台 / 行政人事部

## 1. 产品边界

KPI中心是绩效结果的唯一生成、复核、锁定和归档位置。PMS、OTA、任务、巡检、考勤和客户评价系统只提供只读事实；门店后台只展示考核单、提交人工评分、证据和异议，不自行计算或覆盖结果。

第一批支持岗位：集团副总、OTA运营经理、OTA运营助理、门店店长、店助、前厅主管、前台员工、客房部负责人、客房服务员。第一期只预置OTA运营经理正式模板，其余岗位由行政人事后台配置或通过考核表导入。

第一期KPI模块不支持兼岗和代理岗位。每名员工每个考核月只能绑定一个考核岗位和一套最终解析后的模板版本；底层组织中心已有的多任职能力保持不变。

## 2. 固定考核周期

- 第1周：1日至7日，8日10:00前生成。
- 第2周：8日至14日，15日10:00前生成。
- 第3周：15日至21日，22日10:00前生成。
- 第4周：22日至月末，次月1日10:00前生成。
- 月度草稿：次月1日12:00前生成。
- 数据异议：次月2日18:00前。
- 人事、部门及CEO确认：次月3日。
- 正式锁定：次月4日。

周成绩用于过程管理；月度成绩必须从全月累计分子和分母重新计算，禁止平均四周比例。

## 3. 模板与指标

模板使用集团基础、岗位模板、门店补充的版本链；解析优先级为周期门店版本、周期岗位版本、集团基础版本。发布版本不可修改，只能复制生成未来周期的新版本。

指标类型包括目标达成、完成率、按时完成、事件扣分、条件判定、里程碑、人工评分、奖金调整和组合公式。周度分解支持每周目标不变、四周等额、自定义四周比例、截止日期归属、里程碑和仅月末确认。只有可累加总量型指标可按25%等额拆分；比率与门槛指标每周保持原目标。

人工评价人直接录入0至指标满分范围内的分数，必须同时提交说明和证据。指标、板块及最终成绩支持负分；最低分由模板单项配置，不设全局0分封底。

## 4. 数据状态与审计

指标事实统一使用AVAILABLE、PENDING_VERIFICATION、NOT_APPLICABLE、UNAVAILABLE四种状态。必要数据缺失时生成待核验考核单，不得用0分代替，也不得正式锁定。

事实、模板发布版本、考核单修订、人工评分和锁定结果只允许追加。所有更正生成新版本，保留操作者、服务器时间、来源记录、内容哈希、修改原因和前后差异。

## 5. 结果、预警和奖金

计算顺序：指标得分、板块得分、基础总分、额外加减分、最终绩效分、绩效系数、岗位奖金调整、考勤系数、实发绩效奖金。奖金金额最低为0元；岗位奖金调整必须在岗位模板中单独配置，OTA的RevPAR每店正负500元不得自动继承到其他岗位。

周度预警：单周指标未达标为黄色；同一指标连续2周未达标为橙色并创建改善任务；连续3周未达标或命中模板重大条件为红色。周预警不重复扣分。

## 6. 权限与审批

- 行政人事：模板、考核关系、周期生成、考勤与奖金基数、复核和导出。
- 部门负责人：授权范围人工评分、证据、业务复核和改善任务。
- 员工本人：本人考核单、证据和异议。
- 门店店长：本店相关明细及员工周度总成绩，不查看其他门店经营明细和个人奖金。
- CEO：模板发布、重大异议、最终锁定和奖金政策审批。
- 数据服务账号：只写标准指标事实，不具备人工评分和规则权限。

## 7. 生产门禁

KPI中心不保存PMS密码、OTA Cookie、Token或住客个人信息。真实PMS、OTA和Cookie采集需要独立授权、只读范围和持久化证据；本次开发只建立接口契约、标准事实入口和模拟测试，不放行真实连接、自动改价、关房或库存修改。
