# Sprint 1 技术实施计划

周期建议：2 周。若团队少于 4 人，调整为 3—4 周，但验收范围不变。

## Sprint 目标

建立可扩展、可隔离、可配置的 Hotel AI OS 基础底座，为 Sprint 2 的规则与任务闭环提供稳定数据契约。

## 工作分解

### S1-01 工程与数据底座

- 建立前后端、数据库和文档目录。
- PostgreSQL 迁移、审计字段、Outbox 预留。
- 请求关联 ID、统一异常格式、健康检查。

完成标准：全新数据库可按顺序执行迁移；核心表具备租户字段、唯一约束和索引。

### S1-02 组织与权限

- 租户、品牌、集团、区域、门店、部门。
- 员工、岗位和带生效期的一人多岗任职。
- 角色、权限、角色授权及组织数据范围。
- 应用层租户过滤与 PostgreSQL RLS 第二道防线。

完成标准：两个租户数据不可互查；店总只能访问授权门店；一名员工可拥有多个有效任职。

### S1-03 Standard Center 基础版

- 标准分类、标准定义、草稿版本。
- 集团/品牌/组织/岗位适用范围。
- 发布、废止与版本不可变约束。
- 标准条目、判断条件、证据要求和评分配置使用结构化 JSON Schema。

完成标准：标准可以创建新版本、选择范围、发布，并能追溯发布人和发布时间。

### S1-04 双入口数据基础

- 版本化表单定义和岗位工作记录。
- 附件元数据及对象存储键。
- 经营指标定义、业务日期、数据来源和录入。
- 所有记录关联员工当时的任职关系。

完成标准：四个试点角色能看到对应表单；店总可录入经营数据；重复来源记录被幂等约束阻止。

### S1-05 驾驶舱框架

- CEO：组织规模、门店概览、标准覆盖、指标概览和风险占位。
- 店总：本店经营指标、岗位工作提交、标准执行和待办占位。
- 暂不实现复杂分析和 AI 结论。

完成标准：不同身份看到不同导航和数据范围，移动端无水平溢出。

### S1-06 质量与交付

- OpenAPI 接口文档。
- 后端单元/隔离测试源代码。
- 前端无依赖原型和浏览器截图。
- 页面功能说明、测试报告及 Sprint 2 计划。

## 明确不做

自动调价、复杂 OTA 接口、多 Agent 自主协作、自动晋升、自动处罚、大规模数据仓库。
